# Память калькулятора: контракт для интеграции #6

`CalculatorMemory` в `lib/calculator/domain/calculator_memory.dart` хранит одно `double?` в текущей сессии. Новый экземпляр пуст; сохранения на диск нет.

- `value` — полное числовое значение; `null` означает пустую память, `0` — сохранённый ноль.
- `add(currentResult)` — M+: первое добавление начинается с нуля. `null` ничего не меняет. Неконечное число или переполнение суммы вызывают `MemoryException` с русским сообщением; прежняя память сохраняется.
- `recallExpression()` — текст для MR либо `null` для пустой памяти. Повторный вызов не меняет значение. Отрицательное число заключено в скобки, ноль записывается как `0`, прочие числа — через `double.toString()` для сохранения точности. Научная запись поддержана парсером в PR #9.
- `clear()` — MC: очищает только память. Для AC этот метод вызывать нельзя.

## Контракт экрана для #5

Экран принимает необязательный `CalculatorSessionController` через `session`. Внешний владелец освобождает свой контроллер; без параметра экран создаёт и освобождает собственный. Контроллер содержит актуальный числовой результат и память, уведомляет экран стандартным `ChangeNotifier`.

Интеграция #5 вызывает `session.publishResult(value)` после успешного вычисления и `session.invalidateResult()` при ошибке или смене DEG/RAD. Экран сам сбрасывает результат при изменении выражения, AC, MR и перед отправкой запроса вычисления. M+ доступна только при актуальном результате; UI перехватывает `MemoryException` и обновляет индикатор. Неконечное значение в `publishResult` отклоняется с `ArgumentError` и сбросом прежнего результата — вычислитель должен отсеивать его ранее.

MR вставляет `recallExpression()` через общий `_insertText` с учётом выделения. При пустой памяти MR недоступна. Индикатор использует форматтер результата, но MR использует полную числовую запись. MC сохраняет выражение и числовой результат. AC очищает выражение, результат и сообщение, сохраняя экземпляр памяти. В верхнем ряду находятся MC/M+/MR/AC, удаление символа перенесено к `=`.

Unit-тесты контроллера проверяют актуальность результата и независимость памяти. Widget-тесты проверяют команды очистки, накопление, MR поверх выделения и доступность кнопок, передавая результат через публичный контракт. Это не проверка реального вычисления: #6 остаётся открытой до интеграции #5 и нативной проверки полного сценария `5 → M+ → 3 → M+ → AC → MR`, ошибок и DEG/RAD. Полный парсер из PR #9 также нужен для повторного вычисления текста MR.
