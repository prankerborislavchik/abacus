# Память калькулятора: контракт для интеграции #6

`CalculatorMemory` в `lib/calculator/domain/calculator_memory.dart` хранит одно `double?` в текущей сессии. Новый экземпляр пуст; сохранения на диск нет.

- `value` — полное числовое значение; `null` означает пустую память, `0` — сохранённый ноль.
- `add(currentResult)` — M+: первое добавление начинается с нуля. `null` ничего не меняет. Неконечное число или переполнение суммы вызывают `MemoryException` с русским сообщением; прежняя память сохраняется.
- `recallExpression()` — текст для MR либо `null` для пустой памяти. Повторный вызов не меняет значение. Отрицательное число заключено в скобки, ноль записывается как `0`, прочие числа — через `double.toString()` для сохранения точности. Научная запись поддержана парсером в PR #9.
- `clear()` — MC: очищает только память. Для AC этот метод вызывать нельзя.

## Что ещё нужно подключить на экране

Этот PR реализует только независимый модуль и его unit-тесты; #6 остаётся открытой.

После интеграции #5 экран хранит актуальный числовой результат отдельно от строки отображения. Редактирование, ошибка и смена DEG/RAD делают его неактуальным. M+ доступна только при актуальном результате; UI передаёт его в `add`, перехватывает `MemoryException` и обновляет индикатор.

MR вставляет `recallExpression()` через общий `_insertText` с учётом выделения. При пустой памяти MR недоступна. Индикатор может использовать форматтер результата, но MR использует полную числовую запись. MC сохраняет выражение и результат. AC очищает выражение, результат и сообщение, сохраняя экземпляр памяти.

Остаются тесты команд очистки и переходов состояния экрана, кнопки/индикатор и нативная проверка полного сценария `5 → M+ → 3 → M+ → AC → MR`, ошибок, недоступности M+ и узкого окна. Модуль сам не определяет актуальность результата — это ответственность состояния экрана из #5.
