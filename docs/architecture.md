# Структура калькулятора

Реализованы редактирование, валидация и вычисление выражения, переключатель DEG/RAD, а также UI памяти. M+ недоступна без актуального числового результата, MR — без памяти. AC и MC подключены. Контракт интеграции результата и памяти описан в [calculator-memory.md](calculator-memory.md).

## Что уже есть

```text
lib/
  main.dart
  app.dart
  calculator/
    presentation/
      calculator_screen.dart
      widgets/
        expression_display.dart
        calculator_keypad.dart
        calculator_key.dart
        calculator_notice.dart
        desktop_menu.dart
```

`app.dart` задаёт тему и начальный экран. `CalculatorScreen` владеет `TextEditingController` и `FocusNode` поля. Параметры `expression`, `result` и `notice` задают начальное состояние; `session` передаёт контроллер числового результата и памяти. Без внешнего контроллера экран создаёт собственный. Изменение текста скрывает прежние результат и сообщение; перемещение курсора или выделение их не скрывает. `ExpressionDisplay` использует тот же контроллер для редактирования Flutter с ограничением алфавита: ASCII-цифры, латиница обоих регистров, `+ - * / % ^ ( ) . ,` и обычный пробел. Запрещённый ввод отклоняется без изменения текста и выделения. Вставка проверяет исходный буфер до обработки однострочным полем: любой запрещённый символ отклоняет её целиком с отдельным SnackBar. Клавиатурное сочетание, нативное и контекстное меню используют одну проверку. Отказ не скрывает прежние результат и диагностику. Проверка синтаксиса и вычисление во время набора не выполняются.

`CalculatorKeypad.onInsert` передаёт текст для вставки, `onBackspace` удаляет выделение либо предыдущий символ. Экран заменяет выделение, ставит курсор после вставки и возвращает фокус полю. MR уже использует общий `_insertText`: модуль памяти передаёт готовую строку, заключая отрицательное значение в скобки. Память отображается из `session.memoryValue`, а не из строкового параметра виджета.

Соответствие кнопок записи выражения: `×` → `*`, `÷` → `/`, `−` → `-`, `xʸ` → `^`, `√x` → `sqrt(`, `⌊x⌋` → `floor(`, `⌈x⌉` → `ceil(`, `sin` → `sin(`, `cos` → `cos(`. Цифры, `.`, `%`, `+`, `(` и `)` вставляются как показано. Функция заменяет выделение своим префиксом, не оборачивает его; аргумент и закрывающую скобку пользователь вводит сам. Незавершённые и ошибочные строки допустимы.

Enter и `=` используют один обработчик `_submitExpression`: `ExpressionParser.parse` возвращает AST, `evaluate(ast, angleMode: mode)` вычисляет его, а `session.publishResult(value)` сохраняет полный числовой результат. Экран форматирует его только для отображения через `formatResult`; M+ получает исходный `double`. Перед разбором экран сбрасывает прежний результат через `session.invalidateResult()`, сохраняя память. `ParseException` и `EvaluationException` показываются через `CalculatorNotice`, выражение сохраняется. Повторный запуск заново вычисляет текущую строку; после успеха редактируется исходное выражение.

Режим углов хранится в состоянии экрана и начинается с `AngleMode.deg`. Видимый переключатель DEG/RAD передаёт выбранный режим вычислителю для sin/cos. Смена режима скрывает результат и сообщение, отключает M+ до следующего успешного вычисления и возвращает фокус полю, сохраняя выражение и память. Само переключение вычисление не запускает.

`DesktopMenu` на macOS связывает команды нативного меню Edit и их сочетания клавиш с действиями Flutter для текущего поля. Это сохраняет синхронизацию выделения и буфера обмена с контроллером; на остальных платформах используются стандартные сочетания Flutter.

`CalculatorNotice` отображает переданные текст и уровень сообщения (предупреждение или ошибка). Отсутствие сообщения скрывает этот блок. Компонент не определяет, корректно ли выражение, и не выбирает текст ошибки за валидатор.

## Границы логики и интерфейса

В `lib/calculator/domain/` располагаются общий AST и исключения (`expression_node.dart`), парсер (`expression_parser.dart`), вычислитель (`expression_evaluator.dart`) и форматтер (`result_formatter.dart`). Это обычный Dart без импорта Flutter и обращения к виджетам. Числовая память (`calculator_memory.dart`) размещается там же. Unit-тесты — в `test/calculator/`. `CalculatorSessionController` в presentation хранит актуальный числовой результат и связывает экран с памятью через `ChangeNotifier`.

`const ExpressionParser().parse(String)` возвращает `ExpressionNode` либо бросает `ParseException` с русским сообщением и позицией (от 1). Рекурсивный спуск сохраняет согласованные приоритеты; степень правоассоциативна и сильнее унарного минуса, отрицательный показатель допустим. Глубина вложенных скобок, функций, унарных минусов и степеней ограничена 200 конструкциями: превышение даёт `ParseException` с понятным сообщением, а не переполнение стека. Поддерживаются повторный унарный минус, `.5`, `5.`, десятичная запятая и научная запись (`1e-3`, `2E+2`) для совместимости с числовым представлением MR. Унарный плюс не поддерживается. Имена функций чувствительны к регистру; обычные пробелы разрешены между токенами, но не внутри чисел и имён. Числовой литерал должен быть конечным `double`; переполнение литерала — ошибка разбора. Математические ошибки операций остаются ответственностью вычислителя. Глубина дерева при вычислении ограничена 512 узлами: длинные цепочки операций без скобок также получают `EvaluationException` с сообщением «Слишком сложное выражение» вместо переполнения стека. Эти уточнения грамматики покрыты тестами и подлежат ревью совместно с автором #5.

Состояние экрана и обработчики событий добавляются в `lib/calculator/presentation/` по мере появления задач. Для такого объёма достаточно стандартных средств Flutter; отдельный state-management пакет заранее не требуется.

Пользователь сначала составляет выражение, затем запрашивает результат через `=`. Редактирование само по себе не запускает вычисление.

Грамматика, приоритеты операций, единицы углов, вычислительные ошибки и команды памяти согласованы в [спецификации #2](https://github.com/prankerborislavchik/abacus/issues/2). Общий интерфейс парсера и вычислителя уточняется в соответствующих задачах. Очистка выражения и очистка памяти — разные предметные действия.

Требования к тестам описаны в [README](../README.md#проверки). Термины проекта — в [CONTEXT.md](../CONTEXT.md).

## Нативные платформы

`macos/`, `windows/` и `linux/` — стандартные проекты запуска и сборки Flutter для этих ОС: Xcode/Swift на macOS, CMake/C++ на Windows и Linux. Они хранятся в Git; общий интерфейс и логика приложения находятся в `lib/`. Генерируемые кеши и результаты сборки исключены через `.gitignore`. Подробнее — [desktop-поддержка Flutter](https://docs.flutter.dev/platform-integration/desktop).
